title: Adaptive layouts
description: Swap the whole model at container breakpoints with useResponsiveModel.

A dashfoo layout is already fluid: panels are weight-based percentages, so the
whole tree scales with its container at any size. What it does not do on its own
is _restructure_ at a breakpoint — collapse a three-pane terminal into a single
scrollable column on a phone. That is what `useResponsiveModel` and `stackModel`
add, and they stay headless: you describe the breakpoints and the models; the
library decides which one is active.

## The two pieces

- **`stackModel(model, orientation?)`** (`@dashfoo/core`,
  [source](https://github.com/pedroapfilho/dashfoo/blob/main/packages/core/src/model/stack.ts)) —
  a pure transform that flattens any layout into a single column (default) of all
  its tabsets, in document order, each with equal weight; a maximized tabset is
  unmaximized. It is the "mobile layout from a desktop layout" building block.
- **`useResponsiveModel({ breakpoints })`** (`@dashfoo/react`,
  [source](https://github.com/pedroapfilho/dashfoo/blob/main/packages/react/src/hooks/responsive.ts)) —
  picks the model for the active breakpoint. It returns `defaultModel`, a `key`
  to remount `<DashfooLayout>` on, the active `breakpoint` id, and a
  `containerRef` to attach to the element it should measure.

## Wiring it up

A breakpoint is `{ id, model, query? }`. The `query` is **either** a container
width (`{ maxWidth: number }`, measured with a `ResizeObserver` on the element you
attach `containerRef` to) **or** a media query (`{ media: string }`, via
`matchMedia`). Omit `query` on the last breakpoint to make it the catch-all.
Breakpoints are evaluated top to bottom; the first match wins.

```tsx
import type { Dashfoo, TabNode } from "@dashfoo/core";
import { model, row, stackModel, tab, tabset } from "@dashfoo/core";
import { DashfooLayout, useResponsiveModel } from "@dashfoo/react";
import type { ReactNode } from "react";
import { useMemo } from "react";

const desktopModel = (): Dashfoo =>
  model(
    row([
      tabset([tab("chart", "Chart"), tab("trades", "Trades")], { id: "left", weight: 2 }),
      tabset([tab("book", "Order Book")], { id: "right", weight: 1 }),
    ]),
  );

const renderPanel = (node: TabNode): ReactNode => <div>{node.name}</div>;

const Dashboard = (): ReactNode => {
  // Memoize so the model identity and the breakpoints array are stable across renders.
  const base = useMemo(() => desktopModel(), []);
  const breakpoints = useMemo(
    () => [
      { id: "mobile", model: stackModel(base), query: { maxWidth: 720 } },
      { id: "desktop", model: base },
    ],
    [base],
  );
  const { containerRef, defaultModel, key } = useResponsiveModel({ breakpoints });

  return (
    <div ref={containerRef} style={{ height: "100%" }}>
      {/* remount on `key` so the new breakpoint's model is seeded */}
      <DashfooLayout defaultModel={defaultModel} factory={renderPanel} key={key} />
    </div>
  );
};

export { Dashboard };
```

Keying off `containerRef` (not the viewport) is deliberate: a docking layout often
lives inside a sidebar or split, so it should react to _its own_ width, not the
window's. If you do want the window, use a `{ media: "(max-width: 720px)" }` query
instead — the two kinds mix freely in one `breakpoints` array.

## The state tradeoff

Switching breakpoints swaps the whole model, so a rearrangement the user made on
desktop is not carried into the mobile layout (and back). That is usually what you
want — the two layouts are different on purpose. If you need per-breakpoint
rearrangements to persist, give each breakpoint its own
[`persist` key](/persistence) — a distinct storage key per breakpoint (for
example `layout:desktop` and `layout:mobile`) so each one saves and restores
independently.

## Custom transforms

`stackModel` is one transform; you are not limited to it. A breakpoint's `model`
is a plain `Dashfoo`, so you can hand-author a tablet layout, or write your own
transform over the base model (hide a panel, change weights, move a tabset).
Anything that produces a valid model works.
